## 二、关键函数详细说明

### 2.1 主函数相关

#### `main()` [main.go:9-11]
**用途**: 程序入口函数
**说明**: 简单调用 `cli.Start()` 启动 CLI 框架

#### `cli.Start()` [cli/main.go:21-23]
**用途**: 启动命令行界面
**说明**: 调用 `cmd.Execute()` 开始 Cobra 框架的命令处理

### 2.2 Cobra 命令框架相关

#### `cmd.Execute()` [cli/cmd/root.go:121-132]
**用途**: Cobra 框架执行入口
**说明**:
- 设置自定义的 UsageFunc
- 设置帮助模板
`- 禁用默认命令自动补全
- 设置版本信息
- 调用 rootCmd.Execute() 解析命令行参数

#### `init()` [cli/cmd/root.go:136-154]
**用途**: 全局变量和参数初始化
**说明**: 在包加载时自动执行，注册全局命令行参数：
- `--debug` / `-d`: 启用调试日志
- `--btf` / `-b`: BTF 模式 (0:自动, 1:core, 2:non-core)
- `--hex`: 十六进制输出
- `--mapsize`: eBPF map 大小
- `--pid` / `-p`: 目标进程 ID
- `--uid` / `-u`: 目标用户 ID
- `--logaddr` / `-l`: 日志输出地址
- `--eventaddr`: 事件收集器地址
- `--ecaptureq`: ecaptureQ 模式
- `--listen`: HTTP 配置服务器监听地址
- `--tsize` / `-t`: 文本模式截断大小
- `--eventroratesize`: 事件收集器文件轮转大小

### 2.3 环境检测相关

#### `detectEnv()` [cli/cmd/env_detection.go:66-78]
**用途**: 综合环境检测
**说明**: 依次调用 `detectKernel()` 和 `detectBpfCap()`

#### `detectKernel()` [cli/cmd/env_detection.go:26-46]
**用途**: 检测内核版本是否符合要求
**说明**:
- 获取当前内核版本
- x86_64 架构要求内核 >= 4.18
- arm64 架构要求内核 >= 5.5
- 不符合则返回错误

#### `detectBpfCap()` [cli/cmd/env_detection.go:47-64]
**用途**: 检测 BPF 权限
**说明**:
- 检查进程是否有 CAP_BPF 权限
- 或者是否有 CAP_SYS_ADMIN 权限
- 没有权限则返回错误

### 2.4 TLS/OpenSSL 命令相关

#### `openSSLCommandFunc()` [cli/cmd/tls.go:62-67]
**用途**: TLS 命令执行函数
**说明**:
- 处理 pcapfilter 参数

## 五、关键流程说明

### 5.1 模块注册流程
1. 各模块的 `init()` 函数在包加载时执行
2. 调用 `RegisteFunc()` 将构造函数注册到 `newModule` map
3. 运行时通过 `GetModuleFunc()` 获取构造函数
4. 调用构造函数创建模块实例

### 5.2 eBPF 程序加载流程
1. `MOpenSSLProbe.start()` 设置 eBPF manager
2. 配置 uprobe/tc 挂载点
3. 设置常量编辑器（pid、uid 等）
4. 从 assets 加载编译好的 .o 文件
5. 调用 `bpfManager.InitWithOptions()` 初始化
6. 调用 `bpfManager.Start()` 挂载到内核

### 5.3 事件处理流程
1. eBPF 在内核中捕获事件
2. 事件写入 eBPF map（perf/ringbuf）
3. 用户态 reader 读取事件
4. 调用 `Decode()` 解码为事件结构
5. 调用 `Dispatcher()` 分发事件
6. 事件进入 `EventProcessor`
7. 分发到对应的 `eventWorker`
8. Worker 处理并输出

### 5.4 配置重载流程
1. HTTP API 接收新配置
2. 验证配置有效性
3. 发送到 `reRloadConfig` 通道
4. 主循环接收新配置
5. 设置 `isReload = true`
6. 调用 `mod.Close()` 关闭旧模块
7. 调用 `mod.Init()` 初始化新配置
8. 调用 `mod.Run()` 启动新模块

## 六、错误处理

### 6.1 启动阶段错误
- 环境检测失败：程序退出
- 配置校验失败：程序退出
- eBPF 加载失败：程序退出

### 6.2 运行时错误
- 事件读取错误：记录到日志，继续运行
- Worker 错误：发送到错误通道，继续运行
- 解码错误：跳过该事件，继续运行

## 七、性能优化点

1. **事件通道缓冲**: 使用缓冲通道避免阻塞
2. **Worker 复用**: 使用引用计数管理 Worker 生命周期
3. **批量输出**: Worker 定时批量输出事件
4. **延迟销毁**: 连接关闭后延迟 3 秒销毁，确保事件处理完成

---

## 八、注意事项

1. **权限要求**: 需要 root 权限或 CAP_BPF/CAP_SYS_ADMIN 能力
2. **内核版本**: 不同架构有最低内核版本要求
3. **BTF 支持**: 推荐使用 CO-RE 模式（BTF）
4. **容器环境**: `在容器中运行需要特殊处理 BTF`
5. **信号处理**: 支持 SIGINT 和 SIGTERM 优雅退出
6. **配置重载**: 支持通过 HTTP API 动态重载配置
